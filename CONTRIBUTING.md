# Contributing to health-components (CareOS)

This repository is the production implementation of the **CareOS design system**: design tokens, 123 React
components, Web Components for Angular, Vue and plain HTML, a Storybook and a documentation site.

## Setup

```bash
npm install             # library, Storybook, tests
npm run storybook       # http://localhost:6006
npm test                # unit tests + every story rendered and checked with axe
npm run lint            # ESLint: TypeScript, React hooks, jsx-a11y
npm run typecheck
npm run build           # dist/: ESM + CJS + types, styles.css, tokens, elements
cd website && npm install && npm start   # documentation site
```

## Repository layout

| Path | What |
|---|---|
| `src/tokens/tokens.json` | **Source of truth** for colour (5 themes), type, spacing, radius, shadow, z-index, density. |
| `src/styles/tokens.css`, `src/tokens/tokens.ts` | Generated by `npm run tokens`. Never edit. |
| `src/styles/base.css` | Scoped base layer (focus ring, box sizing, `.co-root`). |
| `src/styles/components.css` | All component styles (`co-*` classes). |
| `src/styles/extra/<Name>.css` | Optional per-component additions; collected into `extra.css` by `scripts/gen-index.mjs`. |
| `src/internal/` | Private helpers: `cx`, hooks (`useControllableState`, `useDomId`, `useDismiss`, `useEscape`, `useFocusTrap`, `useScrollLock`), `Portal`. |
| `src/components/<Name>/` | One folder per component (see below). |
| `src/elements/` | Custom-element wrapper and the generated element registry. |
| `src/index.ts` | Generated by `scripts/gen-index.mjs` from the component folders. Never edit. |
| `.storybook/` | Storybook config, theme switcher, story-only helper CSS (`pv-grid`, `pv-label`, `pv-stack`). |
| `website/` | Docusaurus documentation site. Component pages are generated by `npm run docs:gen`. |
| `test/stories.test.tsx` | Renders **every story** (DOM and server) and runs axe on it. |
| `test/elements.test.ts` | Custom-element behaviour: attributes, properties, slots, events. |
| `examples/angular/` | A standalone Angular app using the custom elements; built in CI. |

## Component folder

```
src/components/Button/
  Button.tsx          implementation + exported props interface(s)
  Button.stories.tsx  Storybook stories (CSF3, autodocs)
  Button.test.tsx     behaviour tests (required for anything interactive)
  README.md           usage guidelines: when to use, variants, props, accessibility, do and don't
  index.ts            export * from './Button';
```

`src/components/Button` is the reference implementation: copy its patterns.

## Rules for components

1. **Class names and DOM structure come from the design system.** Styles live in `components.css` under `co-*`
   classes; components only compose those classes. Do not inline colours or sizes: every value is a token
   (`var(--co-primary)`, `var(--co-radius-md)`), including in inline SVG (`fill: 'var(--co-surface)'`).
2. **Props.** Export a `<Name>Props` interface. Every prop has a JSDoc comment stating its meaning and default
   (`/** 'sm' | 'md' | 'lg'; default 'md' */`): Storybook and the docs site read these. No `any` in a public
   type: export named item types (`MenuItem`, `DataTableColumn<T>`...). Prop names and defaults match the
   design system README so screens built from it keep working.
3. **Native attributes.** The root element accepts `className`. Leaf controls (buttons, inputs, selection
   controls, links) use `forwardRef` and spread the remaining native attributes onto the element.
4. **State.** Anything a user changes (value, open, selected, current step, sort) is uncontrolled by default
   (`defaultX`) and controllable (`x` + `onXChange`/`onChange`) via `useControllableState`.
5. **Overlays** (Modal, Drawer, SuccessDialog, CommandPalette, BreakTheGlassDialog...) render through `Portal`,
   trap focus (`useFocusTrap`), lock page scroll (`useScrollLock`), close on Escape (`useEscape`) and
   return focus on close. `inline` renders them in place for documentation.
6. **Menus and popovers** close on outside click and Escape (`useDismiss`) and follow the ARIA menu pattern.
7. **Accessibility.** Labels on every control, `aria-describedby` for help and errors, `aria-invalid` on
   error, roles per the WAI-ARIA Authoring Practices, keyboard support (arrows, Home/End, Enter, Escape),
   44px touch targets on phone components. Every story must pass axe (`npm test`).
8. **Ids** come from `useDomId(prefix, props.id)`; never a module counter (breaks SSR).
9. **SSR safe.** No `window`/`document` access during render.
10. **Imports.** Import siblings by file (`../Button/Button`), never from `src/index.ts` (avoids cycles).
    No new runtime dependencies: the package has none besides React.

## Stories

- `title: '<Layer>/<Group>/<Name>'`, for example `Basic/Actions/Button` or `Complex/Clinical/PatientBanner`.
- `tags: ['autodocs']`, a component description in `parameters.docs.description.component`, `argTypes`
  for union props, and a **`Playground`** story driven by `args` so every prop is a control.
- Then one story per meaningful variant or state, using realistic clinical data (names, MRNs, codes).
- Overlays: documentation stories pass `inline`; add one story that opens the real overlay from a button.

## Theming

Themes are `classic` (default), `sidebar`, `rail`, `command`, `dark`, applied with `data-co-theme` on any
element or with `<ThemeProvider theme="...">`. All CSS variables are prefixed `--co-` so they never clash with
a host application's own variables.

## Commits and releases

Conventional commits (`feat(Button): ...`). Releases publish to npm from `main` via
`.github/workflows/release.yaml`; the docs site and Storybook deploy to GitHub Pages via `docs.yaml`.
